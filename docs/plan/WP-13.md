## Build

### Proof step

- Transcribe the fixtures on the Mac, and report word error rate and speed.
- Run `knot-eval speech` on the owner's recordings. It prints word error rate on the read-aloud set. If the recordings are not in the folder yet, the note does not wait for them: it is filed without this run, and the run follows when they arrive.
- Repeat inside an app the probe that found `SpeechTranscriber` unavailable in the iOS Simulator. The first probe was a bare executable in the simulator (docs/architecture.md §20).
- File a short note saying whether the draft `Transcriber` port fits the real API's streaming, cancellation and errors. The note is `docs/notes/WP-13.md`, merged by a pull request that holds nothing else.

### PR 1

- `Transcriber` on `SpeechAnalyzer` and `SpeechTranscriber`: asset installation with status and retry, the choice of English locale, live results, file transcription with time ranges, cancellation and availability.
- The locale is the user's English variant, chosen from `SpeechTranscriber.supportedLocales`. Model assets install through `AssetInventory` (docs/architecture.md §9).
- Transcription runs over a file in ranges and can start from an offset, so that an interrupted job continues from its last range and a long recording finishes across several short runs.
- Live results are for on-screen text. The authoritative transcript comes from transcribing the saved file after stop, so every recording takes one code path (docs/architecture.md §8).
- Every voice segment records the engine, the locale and the OS build that produced its transcript, as `transcription` on `Segment` (docs/architecture.md §4). The transcriber supplies them with each transcript.
- `knot-eval speech`. It reads the owner's recordings, which live in one folder outside every worktree, named by `KNOT_LOCAL_FIXTURES`. The files are named `read-aloud-<number>-<device>.m4a` and `note-<number>-<device>.m4a`. It runs before `knot-eval cleanup`, writes transcripts into the same folder, and prints word error rate on the read-aloud set.
- The owner's recordings stay on the build Mac. They are recordings he makes for the build and chooses himself, not notes from his stream.
- `knot-eval` follows docs/architecture.md §18: `--set synthetic` runs on committed fixtures and `--set local` on that folder. Either one exits with a code when its input or its model is missing. It never waits.
- KnotSpeech exposes one live entry point, which returns the unavailable port until WP-13 fills it in. Fill it in, so that the transcriber is wired in without an edit to `Packages/KnotKit/Sources/KnotApp/`.

## Merge criteria

- `scripts/verify.sh --quick` passes.
- Integration tests pass on a Mac with the model installed, and report "skipped: model unavailable" elsewhere. The merge gate requires the on-device models, and a skipped model test fails it.
- Word error rate on the clean fixtures is at most 8%. WP-13 merges on this synthetic criterion. The merge gate checks no accuracy threshold: the threshold belongs to this package's PR.
- No audio or text reaches a log.
- `Transcriber` passes the contract suite of its port on the Mac, in the package tests.
- In the iOS Simulator the tests use the scripted transcriber.
- The synthetic speech results are committed with the fixtures.
- `knot-eval speech` prints numbers only, and exits with a code when its input or its model is missing.
- The PR reruns the synthetic evaluation. At the gate the orchestrator runs the local one, as for any PR that touches speech or cleanup, and records the numbers.
- Package tests use Swift Testing and UI tests use XCTest, as docs/architecture.md §17 states.

## Failure rules

- `SpeechTranscriber` is not available in the iOS Simulator on the build Mac. Tests there use the scripted transcriber, and the gate does the same.
- Speech is not available on watchOS.
- Until the model assets are installed, voice segments stay `recorded` and show as pending.
- A step that cannot run now is a deferral, not a failure. For speech, that is a model that is not ready. Deferrals are never counted, and the job runs again when the app comes forward or the model's availability changes.
- A recording in which no words are recognised is ready with empty text.
- No port throws an untyped error. Every failure is a named case of WP-02's error taxonomy, as docs/architecture.md §5 lists them. Among them are speech model not installed and audio unreadable.
- Neither `knot-eval` command prints text from the recordings, and nothing derived from them enters a commit, a PR, a log or a test. Examples shown in PRs stay synthetic. The owner's recordings are the one exemption from the synthetic-fixtures rule.
- A PR that changes the cleanup instructions, the guard or the speech settings reruns the cleanup evaluation and `knot-eval`, and states the results before and after.
- The nightly run on `main` reports a model that changed with an update of the operating system.
- No automated test and no agent opens a hardware microphone on the build Mac.
- The synthetic audio comes from WP-04, which says whether it is committed or generated, where tests find it, and the error a test gives when it is absent.
- Read the SDK before using an OS 26 or OS 27 API. Any such API used is named in the PR with the declaration that was read (docs/architecture.md §21).
- v1 has no re-transcription. That is deferred to `TODOS.md`.
