The ruling is the owner's keep-gate ruling. At the keep-gate sitting he rules one of four ways: continue as planned, continue with cuts, revise the spec first, or stop the build. Until that ruling, wave 4 does not start, and that holds back this package. Seven days pass between the M2 checklist and the start of wave 4 work. The orchestrator records the ruling in `docs/decisions/keep-gate.md`.

WP-22 builds the signposts for every target in docs/product-spec.md §14.

## Build

- A measurement for each target in docs/product-spec.md §14: an automated one, or one taken from a checklist.
- A report that sets the measured values against the targets.
- `scripts/verify.sh --perf` measures the times, at milestones and in this package, following the protocol in docs/product-spec.md §14. That section gained four targets, all estimates.
- The time thresholds that left the merge criteria of WP-10 and WP-30 are measured the same way: with 10,000 notes on the Mac, a stream page against 16 ms and a search against 50 ms, and the iPhone's launch against its warm target.
- Measured performance uses XCTest, as docs/architecture.md §17 states.
- First budgets for the waits a person sees: cleanup, conversion after a recording, text arriving in the Mac panel, and export. docs/product-spec.md §14 asks this package to set and measure them.

## Merge criteria

- `scripts/verify.sh --quick` passes.
- Each target has an automated measurement or a checklist row, and the report sets the automated measurements against their targets.
- Package tests use Swift Testing and UI tests use XCTest, as docs/architecture.md §17 states.

## Milestone evidence

- A checklist measurement needs the owner and hardware. Its value is taken at a sitting and closes at the milestone, not at merge. The report then sets it against its target.
- Start latency on a real microphone is measured at the owner's sittings.
- The Watch target is 60 seconds from the stop of a 30-second recording to its transcript on the iPhone, with the phone nearby. It is an estimate that SP-2 calibrates, and the M3 checklist measures it. The M3 row states the condition SP-2 measures: the phone locked and Knot not running.
- The M2 and M4 checklists record the latencies that the diagnostics export reports.
- M6 also needs this package. At M6 Paolo can see the Claude Design handoff applied on all four devices, with accessibility and speed targets met.
- M7 also needs this package.

## Failure rules

- A target that Knot does not meet is corrected with evidence. `docs/product-spec.md` belongs to the orchestrator, so this package asks for the correction in its PR description.
- Time thresholds are not merge criteria (docs/architecture.md §17). The gate asserts query plans and operation counts, and `scripts/verify.sh --perf` measures the times.
- No automated test and no agent opens a hardware microphone on the build Mac. The recorder takes injected audio and refuses the hardware input under test.
- `scripts/verify.sh --perf` takes every build slot (docs/architecture.md §18).
- After WP-04 merges, `docs/checklists/` belongs to the orchestrator.
- The fakes and the fixture builders compile only in a debug build, or in a build that sets `KNOT_FAKES`. `scripts/verify.sh --perf` builds optimised with `-DKNOT_FAKES`, so that the build it measures still has them.
