## Goal

Knot is fully usable with VoiceOver, large text and the keyboard.

## Owns

The plan names no path that this package owns.

## Starts after

| PR | What it holds | Starts after |
|---|---|---|
| 1 | The audit made clean, and the accessibility behaviour confirmed | the ruling; WP-40a; WP-40b; WP-40c; WP-40d |

The ruling is the owner's keep-gate ruling. At the keep-gate sitting he rules one of four ways: continue as planned, continue with cuts, revise the spec first, or stop the build. Until that ruling, wave 4 does not start, and that holds back this package. Seven days pass between the M2 checklist and the start of wave 4 work. The orchestrator records the ruling in `docs/decisions/keep-gate.md`.

This package starts after WP-40 as a whole, which means its four sub-packages.

## Build

- Make the system's accessibility audit clean on every designed cell of the state matrix in docs/design/brief.md §6. Every UI smoke test runs that audit, from WP-21 PR 1 on.
- Confirm that accessibility is behaviour, as docs/product-spec.md §13 states it: VoiceOver announces the start and stop of a recording and stays silent while it runs; new text never moves focus; focus returns when a surface closes; every segment action is reachable from the keyboard on the Mac and the iPad. WP-21 builds this into its components, which have VoiceOver labels and Dynamic Type from WP-21 PR 1. This package confirms it.
- The segment actions include the move of a segment to its own note. Each can be reached from the keyboard on the Mac and the iPad.

## Merge criteria

- `scripts/verify.sh --quick` passes.
- An Accessibility Inspector audit is clean on each platform.
- The system's accessibility audit is clean on every designed cell of the state matrix.
- The Mac and iPad work without a pointer.
- Package tests use Swift Testing and UI tests use XCTest, as docs/architecture.md §17 states.
