## Build

- Note to Markdown, with small flat front matter (ID, created, updated).
- Share items for text, Markdown, audio and image.
- Export of everything, with deterministic file names: a folder of Markdown files with their recordings and drawings (docs/product-spec.md §8).
- Export never downloads. It exports the recordings and drawings that are on this device, writes a line in the note's Markdown for a file that is on another device, and returns the list of what it left out (docs/architecture.md §3). It can also say what an export would leave out before it writes anything, which is how `knot export` refuses and writes nothing.
- A drawing's image comes from the caller, through a provider of KnotCore types that the caller passes in: with an image KnotExport exports the drawing as that image, and without one it writes the drawing's stored data file under its ID and names it in the list. Export never drops a drawing, so `knot export`, which cannot reach KnotInk, still exports everything (docs/product-spec.md §10). WP-20 does not wait for the port of WP-02 PR 3 that gives a stored drawing's image. Until WP-18 merges nobody has an image to pass, and ink is gated off until M5, so no milestone build holds a drawing before then (docs/architecture.md §3 and §10).
- WP-33 uses KnotExport for the Markdown of a note that is dragged out of the Mac main window.

## Failure rules

- A recording or a drawing may still be on another device. docs/product-spec.md §8 and §10 say what export does then. The app downloads them first through `AssetFetcher`, then exports, and shows the list of what KnotExport left out. `knot export` never downloads: it asks KnotExport first, and refuses and writes nothing when a file is on another device, or with `--skip-missing` exports the rest with that list.
- A sandboxed tool probably cannot write to a folder given as an argument, so SP-3 decides how `knot export` delivers its output (docs/architecture.md §15).
- Importing an export is deferred to `TODOS.md`.
