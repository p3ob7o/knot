## Build

### PR 1

- PR 1 is the scaffold: the targets, both build flavours, the local configuration, `scripts/bootstrap.sh`, `scripts/doctor.sh` and `scripts/verify.sh --quick`.
- `Packages/KnotKit/Package.swift` with every module in `docs/architecture.md` §3 as an empty target with one trivial test, GRDB pinned to an exact version, and platform minimums of 27. The targets include KnotFakes, KnotTestSupport, KnotUIPreviews and `knot-eval`.
- GRDB's revision is pinned as well as its version, and `scripts/verify.sh` checks it for SwiftPM and for Xcode, because the generated project's lock file is not committed.
- A crash-host executable for KnotStore, for KnotAudio, for KnotLink and for KnotInk, and the soak's child, because a kill test needs a process to kill. Their sources are `Packages/KnotKit/Sources/KnotStoreCrashHost/`, `KnotAudioCrashHost/`, `KnotLinkCrashHost/`, `KnotInkCrashHost/` and `KnotSoakChild/`, and each belongs to its module's package once WP-01 has merged.
- KnotFakes and KnotUIPreviews compile only in a debug build, or in a build that sets `KNOT_FAKES`, because Xcode links a package product into every configuration.
- Each module exposes one live entry point that returns the unavailable port until its package fills it in, so WP-16, WP-17, WP-18 and WP-19 wire themselves in without editing `Packages/KnotKit/Sources/KnotApp/`.
- XcodeGen targets, one YAML file per target, included from `project.yml`: `Knot-iOS` (universal), `Knot-watchOS` (a companion embedded in the iOS app), `Knot-macOS`, `Widgets-iOS`, `Widgets-watchOS`, and the `knot` executable embedded in the Mac app. Each app launches to a placeholder showing the mark.
- Entitlements and Info.plist keys: microphone usage string, background audio, app group, iCloud with CloudKit, push. Identifiers are constants in one xcconfig.
- Knot has one window on the iPad, as `docs/product-spec.md` §6 states.
- Every target has a privacy manifest that declares a required reason for each API that needs one.
- Both build flavours. Every build that is not a milestone build uses development identifiers: the bundle ID with a `.dev` suffix, its own app group and its own iCloud container. That covers agent builds, PR builds, spikes and tests, and tests also pass the store path in. A development build installs the tool as `knot-dev`.
- Milestone builds reuse `com.p3ob7o.knot`, with the app group `group.com.p3ob7o.knot` and the iCloud container `iCloud.com.p3ob7o.knot`. The Mac's app-group form stays open until SP-3 reports. Milestone builds carry a version above 0.2.0, which is the retired app's.
- A milestone build has a level, and WP-01 builds the mechanism. Every milestone build, and every fix built for an earlier milestone, is made at a level from M1 to M7. A feature whose milestone has not passed is switched off in it by a gate: sync and the command line open at M4, and ink at M5. WP-22 builds the test that lists the gates for each level.
- A local build configuration for tests and agent builds. It keeps the sandbox and leaves out the entitlements that need the owner's signing profile, with sync off. An optional `Local.xcconfig` serves a contributor's own team.
- The signing team's ID stays out of the repository, as `docs/architecture.md` §18 states. `KNOT_LOCAL_CONFIG` names the local file, beside `KNOT_LOCAL_FIXTURES`.
- Each worktree's development builds keep their own store and their own recording state. The Mac development store sits in the development container, in a folder named for the worktree.
- The environment factory in `Packages/KnotKit/Sources/KnotApp/`. A debug build asks KnotFakes for the preview environment, which answers `.unavailable` until WP-05 fills it in. WP-05 therefore edits only its own folders. PR 1 declares `AppEnvironment` in KnotCore with its `.unavailable` value and nothing else, because the factory returns that value. That is a stated exception to path ownership (PLAN.md §8.5), and WP-02 extends the type as its ports land.
- Swift 6 mode, strict concurrency complete, warnings as errors.
- The availability rule, stated: the deployment target is 27.0, an API that first shipped in 27.1 or later is guarded or raises the stated minimum, and code must compile with the release Xcode installed at G1.
- `.xcode-version`, committed. It records the version of the release Xcode 27 that the owner installs beside the beta at G1, which is the Xcode for the merge gate and for the archive. Every script sets `DEVELOPER_DIR` from it and checks the version. Implementers use that Xcode, and the beta only by name.
- `scripts/sdk-path.sh`, which replaces the fixed path of `docs/architecture.md` §21. WP-01 checks every row marked "SDK" in `docs/architecture.md` §20 against that Xcode's SDK.
- `scripts/bootstrap.sh`, `scripts/doctor.sh` and `scripts/verify.sh --quick`. `scripts/verify.sh` follows `docs/architecture.md` §18: one tier per run; `--only` and `--module`; one summary line; and a failed step that names its log and its rerun command. `scripts/doctor.sh` runs first.
- `scripts/doctor.sh` has a floor of free disk space. It prints the two commands with which the owner enables Automation Mode and developer mode. It probes that the gate's development-signed step can sign without a prompt. It refuses a repository, a build folder or a fixtures folder that a cloud file provider syncs.
- `scripts/lib/fail.sh`. Every script reports failure through it.
- `scripts/sim.sh`, and per-worktree DerivedData. The index store is off for agent builds, and each worktree has a small fixed set of simulators.
- The watchOS 27 simulator runtime, installed, with the command documented. Only iOS runtimes are on the machine today.
- A GitHub Actions workflow running `verify.sh --quick`, if a hosted runner offers Xcode 27. If none does, say so in `docs/dev-setup.md`. The repository gets no self-hosted runner, and its workflows hold no secrets and pin their actions.
- `docs/dev-setup.md` lists each prerequisite with its version and the command that installs it.
- The packaging that otherwise fails late, proven with one trivial instance of each and a check in `verify.sh`:
  - an App Intent declared in the package and present in both the app and the widget extension;
  - a Live Activity attributes type;
  - the watch app embedded in the iPhone app;
  - the `knot` tool embedded and signed in the Mac app;
  - a contract suite in KnotTestSupport run from two test targets;
  - a Release binary free of KnotFakes.
- Until PR 2 merges, the gate is `--quick`, listed as an exception in `scripts/gate-steps.txt`.

### PR 2

- PR 2 is the tooling: `--full`, `--gate`, `--perf`, the slots, the install script, the ownership check, `scripts/status.sh`, `scripts/worktree-remove.sh` and the scripts' self-test.
- `scripts/verify.sh --full`. `--skip mac-ui` exists for implementers, and the gate refuses it.
- `scripts/bootstrap.sh` generates the audio fixtures with `Fixtures/tools/generate.sh --audio`, because audio made with the system voices is not committed. `scripts/verify.sh` runs `Fixtures/tools/generate.sh --check`.
- The gate refuses `KNOT_XCODE` when it names another Xcode than `.xcode-version` pins.
- `scripts/verify.sh --gate` is the merge gate, run on the orchestrator's Mac. It builds with the release Xcode. It requires the on-device models and fails on a skipped model test, but it checks no accuracy threshold: thresholds belong to the package PRs that own them and to the milestones.
- The gate requires both models on the Mac and uses the scripted transcriber in the iOS Simulator, where the real one is not available.
- The gate picks its depth from the diff by a fixed table and refuses a partial run, as `docs/architecture.md` §18 states. It adds the soak from the diff. It fails when a test listed in `docs/plan/named-tests.txt` is missing once its package has merged.
- The gate's lint fails on:
  - `UserDefaults.standard`, because v1 keeps its settings in a named defaults suite;
  - `@AppStorage` without a named store, and an autosave name without the `v1.` prefix, because the system writes those into the standard domain;
  - GRDB's `eraseDatabaseOnSchemaChange`;
  - an API that needs a required reason and has none declared;
  - a file whose name ends in " 2".
- A lint keeps `@unchecked Sendable`, `nonisolated(unsafe)` and `@preconcurrency` to a reviewed list. The nightly run executes the package tests under Thread Sanitizer. The nightly run on `main` also reports a model that changed with an update of the operating system.
- After G1 and SP-3, the gate has one development-signed step for a PR that touches KnotAgent, `knot`, the Mac app or KnotStore: the sandboxed app and `knot-dev` share a store, the tool writes and the app shows it.
- `scripts/verify.sh --soak`, with `--seed`. The soak step itself belongs to WP-06.
- `scripts/verify.sh --perf` measures times at milestones and in WP-42, following the protocol in `docs/product-spec.md` §14. It builds optimised with `-DKNOT_FAKES`, so that the build it measures still has the fakes. The gate asserts query plans and operation counts, not times.
- `scripts/build-slot.sh` and `scripts/install.sh` follow `docs/architecture.md` §18.
- `scripts/build-slot.sh` keeps heavy builds to three at a time. A slot is a lock that frees itself when its holder dies. The slots are on `/usr/bin/lockf`, with one kept for the gate. Mac UI tests have an exclusive slot. The script also limits how many simulators are booted at once.
- `scripts/install.sh` installs a named build on every paired device with `devicectl` and names any device it could not reach. It exits non-zero when it missed a device.
- `scripts/install.sh` has a path for a Mac: it writes the build to a folder the owner names, and he opens it there. From the M4 milestone build on, no milestone build is installed or run on the build Mac.
- The ownership check.
- `scripts/status.sh`, which prints the status table, as `docs/architecture.md` §18 states. `docs/status.md` has a milestone-evidence column and is written to `main` only at milestones.
- `scripts/worktree-remove.sh`. Removing a worktree removes its development store folder with its simulators.
- The scripts' self-test.

## Failure rules

- This package declares every target and resource folder up front, so later packages do not need to edit `Package.swift` or `project.yml`.
- WP-01 PR 1 has a stated exception to the thread prompt of PLAN.md Appendix B. It starts from a tree with no `scripts/bootstrap.sh` and no `scripts/verify.sh`, so its baseline is that the tree matches WP-00's file list. WP-01 PR 2 runs the baseline step like every other PR.
- Every script reports failure through `scripts/lib/fail.sh`. A failed step of `scripts/verify.sh` names its log and its rerun command.
- The release Xcode cannot compile code written against the beta SDK. The availability rule applies, and the merge gate builds with the release Xcode.
- A development build must not write into the owner's notes. The development identifiers prevent it, with the rule that only a milestone build opens the default store or the real iCloud container.
- If no hosted runner offers Xcode 27, `docs/dev-setup.md` says so.

## Named tests

- `package-tests-under-thread-sanitizer-nightly`: The nightly run executes the package tests under Thread Sanitizer.
- `contract-suite-dummy-port-two-test-targets`: A contract suite in KnotTestSupport run from two test targets, which WP-01 proves with one dummy port before WP-02 relies on it.
- `scripts-self-test`: The scripts have a self-test that `--quick` runs: a slot is released when its holder is killed, a failure prints the agreed fields, and the plan check catches a brief with a missing heading.
