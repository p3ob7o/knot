## Build

### PR 1

- The first PR is a skeleton that does not depend on the design direction.
- The theme layer, with placeholder values. `Packages/KnotKit/Sources/KnotUI/Theme/` holds colour roles, the type ramp, spacing, radii and motion. WP-40 replaces the values from the handoff.
- View models for the stream, a note, capture, search and settings. View models hold the behaviour and are tested without views. Views stay thin, so restyling does not touch logic. Views never touch storage: they talk to view models, and view models talk to ports.
- Components: the stream row, the three segment views with their states, the capture field, record button, waveform, audio player, pending and failed markers, search field and settings forms.
- VoiceOver labels and Dynamic Type from the first PR.
- Accessibility is behaviour, as docs/product-spec.md §13 states it. WP-21 builds it into its components: VoiceOver announces the start and stop of a recording and stays silent while it runs; new text never moves focus; focus returns when a surface closes; every segment action is reachable from the keyboard on the Mac and the iPad.
- The system's accessibility audit runs in every UI smoke test from this PR on. Exclusions sit in one file, each with a reason (docs/architecture.md §17). WP-41 makes the audit clean on every designed cell.
- The previews live in KnotUIPreviews and run on `AppEnvironment.preview`: the fakes, with the real capture engine and queue over them on iOS and macOS.
- The editing model, fixed in docs/product-spec.md §7 as assumption A27. A note is a stack of segments, each edited on its own, a selection does not cross from one segment into the next, and undo covers the segment being edited. New text enters through the capture field, which is the last element of every open note. With the append window open, the capture surface is that note with its field focused, so WP-21 builds one view model for the note and for capture.
- The capture surface follows docs/product-spec.md §4.1. It shows the note a capture would join, following the window, and the destination is fixed at the first keystroke. When the window runs out while the field is still empty, the earlier note leaves the surface, and a view-model test covers that case.
- The append rule has one owner. The note a capture surface shows comes from a store query that calls the same rule as the store's record-a-capture transaction. The view model does not apply the rule itself.
- "New note" is one action away wherever the capture surface shows the note: the iPhone and iPad capture surface, the Mac panel and an open note (rule 4 of docs/product-spec.md §3).
- The six states of a voice segment, named in docs/product-spec.md §5 by what the user can do: saved on the Watch; saved, text on its way; saved, text being made elsewhere; ready; needs you; kept, no text. The mapping from internal states to the six, and the settled rule, live in KnotCore and are built by WP-02. KnotUI uses both. A view-model test covers each of the six states. Retry on another device is labelled as moving the work to this device.
- The stream row follows docs/product-spec.md §7. Its preview is the latest segment's text. A note with no text says what it holds. At large text sizes the preview gives way first, then the kinds. The title or first line, the time and a failed marker always stay. A late capture is marked as arrived until its note is opened, and the stream says once that captures arrived. Opening a note clears its arrival marks through `NoteStore`, by the operation that WP-02 puts in the contract.
- "Move to its own note", as docs/product-spec.md §7 and rule 16 of §3 state, with assumption A37. WP-21 adds the action and its undo to the note's view model. The action sits beside Delete on every segment of a note that holds another live segment. The app undoes it at once, and the window follows the most recent capture into its new note. The app's undo is the store's return. Tests cover when the action is offered and an undo after the note it left was deleted.
- A segment written through the command line or MCP carries a quiet mark. A segment made by a newer Knot says so and asks for an update.
- An open note that is deleted on another device says so and offers to restore it (docs/product-spec.md §7).
- A recording or drawing that was purged after a restored copy was made shows as missing, never as a broken player (docs/architecture.md §7).
- The first-run stream follows the sync state that the build really has. Its view model carries three cases: sync is on; sync is off by the person's own switch; and sync is not available in this build, which is the case for the local configuration of an agent or a test and for a milestone build below M4. When sync is on, the empty stream says that sync is on and where its switch is, the line that docs/product-spec.md §12 gives. When sync is not available, it says nothing about sync. What it says when the person has switched sync off is a wording for the owner: the open point "The first-run line when sync is switched off" of docs/plan/open-points.md. Until he gives it, the stream shows no line about sync in that case. The first-run stream may also carry up to three dismissible rows on setting up the Action Button, a Lock Screen control and the Watch complication (assumption A29). If Live Activities are off, Settings says that recording from the Lock Screen will open Knot.
- When the store is unavailable, captures go to `Inbox/` and the stream says what is wrong.

### WP-21a

- A small pull request beside the two this package planned, by the orchestrator's ruling of 2026-11-21. It holds what the apps' skeletons and the gate found in PR 1 after it merged, and nothing of PR 2.
- The accessibility audit's helper excludes the system keyboard's own interface, by structure and on iOS only. An element of the app with no description still fails while the keyboard is up.
- No text of a stream row is clipped at any text size: the title, the time, and the preview, which the row's model cuts to a short excerpt.
- The placeholder palette's secondary roles pass the audit's contrast check on small text.
- No test of KnotUI rests on how fast it runs: a press is timed on a clock the test moves, and the test store's append window is held open.
- A launch of the Mac app by a UI test or by the launch step ignores saved window state: every development build has the same bundle ID and so shares it, and a window that was closed once would stay closed for all of them.

### PR 2

- The second PR builds from the structure sheets in `docs/design/direction.md`: for the capture surface of each of the four devices, its regions, its navigation, and the component in each state.
- The capture field is the one pump of a typed capture: the engine keeps no session of its own. Its model sends one save at a time, each after the one before has answered, and ends a capture only on text that was saved.
- The model never stays on a typed capture that ended under it, as one ends when a recording or another surface starts (rules 13 and 15 of docs/product-spec.md §3). What that capture saved is in its note. Text the field holds beyond it stays in the field and begins a capture of its own at the next save: the rest of the text when the text the capture ended on begins the field's text, and all of it otherwise. How the surface says that the earlier text was saved is an open point for the design round (docs/plan/open-points.md).
- After a save that failed, the next save sends the field's text whatever it is, even text equal to the last text answered, and an end follows only an answered save of the field's text.
- The destination is fixed when the first keystroke is taken, not when the begin answers (docs/product-spec.md §4.1). From then on the surface shows the note it showed, also on the `Inbox/` path, unless the store answers a different note, which it then shows.
- A begin that throws names its capture, and the model keeps that ID: its next save is an update of that capture, and a field emptied after it ends that capture as empty.
- Nothing is written without a revision that was shown. "Keep mine" writes only on the revision the conflict showed, never with no condition, also when the segment moved or was deleted while the conflict stood.
- The ink segment view and its states, on the ink types of WP-02 PR 3: shown, being recognised, failed, nothing recognised, the last being the cell that shows "Kept, no text", which a drawing that cannot be read shows too, with the placeholder in place of the drawing.
- The ink segment view gets a drawing's image through the port of WP-02 PR 3 that gives a stored drawing's image. Until WP-18 merges, `.live` answers that it is unavailable, and the view shows its placeholder with the recognised text (docs/architecture.md §10).
- Sync status in the settings view model: off, syncing, error, iCloud storage full, no account. When iCloud storage is full, sync says so, and text waits with the recordings while everything stays on the device.
- The state matrix. The matrix that ends docs/design/brief.md §6 has 47 states by six surfaces. WP-21 adds one named preview in KnotUIPreviews for every cell marked as designed, and a test fails when a cell has none. The test reads the state matrix from the brief's own table, so there is no second list. The matrix holds the row "A segment moved to its own note, with undo".
- WP-40's side-by-side screenshots are rendered from those previews.
- `RecordButton` colours `.starting` with the recording role, so the control reads as recording before the recording is live. Until that changes, the Watch's shell passes `.idle` and disables the control while a start is under way. WP-40 meets the same question when it styles the control.

## Failure rules

- If the design handoff arrives late or changes structure, the cost is UI rework. Behaviour lives in view models. Views are thin and restyled in WP-40.
- The design may propose another editing model in the direction step, and the owner must accept it before code depends on it.
- A return is refused when the segment's note has changed since the move, or when the note it left is deleted or gone. It then changes nothing.
- The store decides where a capture goes. The capture surface only shows the store's prediction, and the store's transaction makes the decision.
- When the store is unavailable, capture still works and the stream says what is wrong.

- `voice-segment-six-states-view-model`: A view-model test for each of the six states of a voice segment.
- `move-action-when-offered`: WP-21 adds the move action and its undo to the note's view model, with a test for when the action is offered.
- `move-undo-after-note-it-left-deleted`: WP-21 adds the move action and its undo to the note's view model, with a test for an undo after the note it left was deleted.
