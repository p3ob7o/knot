### PR 2

Everything else:

- `AudioPlayer` and `RecordingStateStore`, the two other ports that WP-12 implements, behind the same live entry point. `AudioPlayer` plays, pauses and seeks a recording. `RecordingStateStore` publishes whether a recording is running, for controls and widgets in other processes. On iOS the recording state sits in the app group container.
- The manifest written before the first sample, and recovery of orphaned recordings. The manifest is a `CaptureManifest`, the one versioned format in KnotCore for a recording in progress.
- Paths come from `StoreLocations`, the only code that computes a store path. Files are placed with `DurableFile`, the only code that places a file: it syncs the file and its folder before the row that points to it is committed. KnotAudio holds no default path, and a file's place on disk comes from its ID.
- The file being recorded is synced to the drive every second. Report what that costs. The target for a sudden power cut is to lose at most the last two seconds of audio, an estimate (docs/product-spec.md §14).
- The heartbeat. The saved recording state can outlive a crash, so the recorder writes a heartbeat into it every second. A state whose heartbeat is older than three seconds is stale: no recording is running.
- Level metering for the waveform. A small array of level peaks is stored beside each recording, written while recording, so that a waveform never needs the audio decoded.
- Interruptions (calls), route changes (AirPods connecting) and the 30-minute cap.
- Conversion to AAC mono `.m4a` after stop, about 0.5 MB per minute, verified before the working file is deleted.
- A hook that hands live buffers to a `Transcriber`, for on-screen text.
- The cues of docs/product-spec.md §4.5. That section lists the cue for each of six events on each device, and WP-12, WP-30, WP-32 and WP-33 implement them.
- One file of kill points in `Packages/KnotKit/Tests/KnotSoak/`, for the capture ledger soak that WP-06 builds.
- A test that feeds 30 minutes of injected audio and counts the same frames out.

## Failure rules

- The watch needs the same guarantees with a small file, about 0.5 MB per minute, because the file travels over Bluetooth.
- If conversion fails, the working file stays as the segment's recording, and the queue retries the conversion.
- A stale recording state is judged by its heartbeat. A press that meets a stale state recovers the orphaned recording and starts a new one, with the started cue. A press never does nothing after a crash.
- In the app process the recorder decides, not the heartbeat: a press stops a recording that this process is running, whatever the heartbeat says. The heartbeat serves the controls and widgets of other processes, and recovery at launch.
- A press while a recording is starting or stopping is ignored.
- If writing fails while a recording runs, for example because the disk filled, the recording stops with the stop cue and its reason, and everything written so far is kept.
- A recovered capture ends at its last durable write.
- A capture belongs to the process launch that began it. Recovery finishes only the captures of earlier launches, so it never ends a recording that is being made now.
- Until the "live" cue, nothing implies that Knot is recording. The "saved" cue is given only after the sync to the drive.
- No automated test and no agent opens a hardware microphone on the build Mac. That holds for the proof step too.
- The synthetic audio comes from WP-04, which says whether it is committed or generated, where tests find it, and the error a test gives when it is absent.
- No port throws an untyped error. Every failure is a named case of WP-02's error taxonomy, as docs/architecture.md §5 lists them. Among them are microphone permission refused, no input device, audio session busy, too little space, conversion failed, and a capture stopped because the disk filled.
- When the soak fails it prints its seed, its kill point and where the store was kept. A soak failure is never retried to green.
- v1 does not stop a recording that hears no speech. That is deferred to `TODOS.md`.
