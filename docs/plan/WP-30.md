## Build

### PR 1

- The first PR is a skeleton that does not depend on the design direction.
- Launch straight into capture with the keyboard up.
- A line typed on the iPhone or the iPad is saved and found in the stream after relaunch. The iPad has the iPhone's layout from M1 on.
- Knot has one window on the iPad (assumption A36). The app's scene manifest allows no second scene, and a test reads that from the built app.
- A UI smoke test on `.live`, the iPhone's. As docs/architecture.md §17 states, it runs the app on `.live` with a temporary store: type, kill, relaunch, read. The other UI tests stay on `.preview`. WP-30 PR 1 merges after WP-22 PR 1, which makes `.live`.

- The second PR builds from the iPhone's structure sheet in `docs/design/direction.md`.
- WP-30a built the structure and most of this list. What it left for this PR is the last point of its section above.

- The stream, the note view with in-place editing, search, delete and undo, and share.
- Export and share pass KnotExport the person's time zone for the day in a file name. The front matter is always in UTC.
- The note view follows the editing model of docs/product-spec.md §7 (assumption A27): each segment is edited on its own, and a selection does not cross from one segment into the next. A UI test checks both.
- Settings, the permission flow, deep links for intents, and a flush on background and termination.

- "Move to its own note", as docs/product-spec.md §7 states. WP-30 builds the action and its undo into the note view. The action sits beside Delete on every segment of a note that holds another live segment. The app undoes it at once, and the window follows the most recent capture into its new note. The UI smoke test moves a segment and undoes the move. The iPad inherits the move, and it can be reached from the keyboard there.
- The cues. docs/product-spec.md §4.5 lists the cue for each of six events on each device, and WP-30 implements those of the iPhone and iPad column inside the app. Until the "live" cue, nothing implies that Knot is recording.

## Failure rules

- The capture surface is on screen before the launch steps run. The steps depend on one another as docs/architecture.md §13 states: the steps that need the store are skipped when it did not open, jobs and sync wait for recovery and ingest, and a step in which the last two launches died is skipped and reported. WP-22 builds the launch sequence.
- Text is flushed on background and termination, as docs/product-spec.md §4.1 states.
- Knot's URL scheme only navigates. It never writes text and never starts a recording.
- A stale recording state is judged by a heartbeat, as docs/architecture.md §8 states. In the app process the recorder itself is the truth: a press stops a recording that this process is running, whatever the heartbeat says. Launch ends a Live Activity that has no recorder.
- The diagnostics file holds no note text, no titles and no content-derived names. Every log line about a capture carries the capture ID.
- The design may propose another editing model in the direction step, and the owner must accept it before code depends on it.
- If the iPad Pencil work is cut, the iPad keeps the iPhone's layout, which it has had since M1, and has no canvas, no side-by-side layout, no hardware-keyboard shortcuts and no menu bar.
