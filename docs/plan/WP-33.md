## Failure rules

- If the hotkey's key is already registered by another app, Settings says so and asks for another key.
- If a key release never arrives, the recording goes on with the panel showing and a stop control. Esc or another press of the hotkey stops it, and Knot checks the key's state every second while recording.
- If hotkey press and release do not arrive in a sandboxed build, the fallback is a listen-only event tap, which needs the Input Monitoring permission. SP-5 decides.
- If first words get clipped when the microphone opens at the 250 ms mark, the alternative is to listen from key-down into a buffer that a tap discards, on built-in and wired inputs only.
- No automated test and no agent opens a hardware microphone on the build Mac. The recorder takes injected audio and refuses the hardware input under test.
- Knot's URL scheme only navigates. It never writes text and never starts a recording.
- Sync and the command line open at M4. In a milestone build made at a lower level, a gate switches them off.
- The standard defaults domain belongs to the retired app's keys. `@AppStorage` is used only with a named store, and every autosave name has the `v1.` prefix, because the system writes those into the standard domain. WP-01's lint fails otherwise.
- The Mac development store sits in the development container, in a folder named for the worktree.
- Mac UI tests need the one desktop session, so they queue on an exclusive slot.
- The diagnostics file holds no note text, no titles and no content-derived names. Every log line about a capture carries the capture ID.
- The design may propose another editing model in the direction step, and the owner must accept it before code depends on it.
