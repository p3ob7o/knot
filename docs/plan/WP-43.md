The ruling is the owner's keep-gate ruling. At the keep-gate sitting he rules one of four ways: continue as planned, continue with cuts, revise the spec first, or stop the build. Until that ruling, wave 4 does not start, and that holds back this package. Seven days pass between the M2 checklist and the start of wave 4 work. The orchestrator records the ruling in `docs/decisions/keep-gate.md`.

If M5 is cut, every condition that names M5 names M4. This package then starts after the ruling and M4.

## Build

- The privacy manifest. Every target has a privacy manifest that declares a required reason for each API that needs one, and WP-01's lint fails on such an API with no reason declared. The manifest declares no collected data (docs/architecture.md §19).
- Usage strings.
- An entitlement audit. docs/architecture.md §19 lists the entitlements.
- Icon sets for every platform from the kept mark, which is in `Resources/Brand/`.
- A `scripts/release.sh` that fails closed. It follows docs/architecture.md §18.
  - It sets `DEVELOPER_DIR` from `.xcode-version` and checks the version, as every script does. That file names the release Xcode that the owner installs at G1, which is the Xcode for the merge gate and for the archive.
  - It reports failure through `scripts/lib/fail.sh`, as every script does.
  - It takes the key as a file path only.
  - It prints variable names only in a dry run.
  - It repeats the check for KnotFakes on the archive, and refuses a binary that honours the preview launch argument.
  - It refuses a candidate that lacks any milestone's evidence. If M5 is cut, every condition that names M5 names M4.
  - It names the release configuration. A milestone build is built in the release configuration, and the default configuration of `project.yml` is Debug.
- A README and short user guide. The README links to setup, the command reference, contributing and recovery.
- Third-party notices. GRDB is the one third-party library.
- The privacy text, in the README and for the App Store. It says exactly what iCloud encrypts end to end and what it does not, checked against Apple's documentation when this package writes it (docs/architecture.md §19). It also says that the command-line switch is consent and not a wall.
- A troubleshooting guide. It holds:
  - one entry for each failure whose behaviour is fixed in docs/architecture.md. The error taxonomy names those failures by case, as docs/architecture.md §5 lists them;
  - the steps to roll a build back. Rolling back never discards work: restoring a pre-migration copy stops the app and the tool, moves the current store folder aside whole and keeps it, and the guide says how to export what was captured since;
  - how to open the retired app's store with the copy of the retired app that the owner kept, if something was missed when he cleared its Recovery window before the first milestone install. v1 leaves that store untouched.

## Failure rules

- Uploading needs Paolo's explicit authorisation and an App Store Connect API key. The key is requested through the secret prompt and never pasted into a thread.
- Each upload needs the owner's word. The API key is handed over for one upload and revoked after it.
- After a failed upload the release script says to check App Store Connect before retrying.
- These also need Paolo's explicit authorisation: moving a tag, distribution signing, notarising, deploying the CloudKit production schema, and every operation on the milestone iCloud container, in either environment.
- The production CloudKit schema cannot drop fields. From the deployment of the production schema on, the CloudKit schema is a committed file, and the gate fails on a change to it that is not additive.
- A release step that was cut short is never resumed. It goes back to the owner (docs/architecture.md §18).
- From the M4 milestone build on, no milestone build is installed or run on the build Mac.
- Milestone builds carry a version above 0.2.0, which is the retired app's. The M7 build is a milestone build.
- The signing team's ID stays out of the repository. `KNOT_LOCAL_CONFIG` names the local file that holds it.
- A package edits only the paths it owns. `Package.swift`, `project.yml`, `AGENTS.md`, `PLAN.md`, `docs/product-spec.md` and `docs/architecture.md` belong to the orchestrator, and a package that needs a change there asks for it in its PR description.
