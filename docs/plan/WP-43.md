### WP-43a

- A pull request ahead of the one this package planned, by the orchestrator's ruling of 2026-11-26. The owner asked that day for the apps on TestFlight once the designs are applied, and answered that the first upload goes as soon as the iPhone's design package has merged, with the other devices as they are. No upload is possible without the script, so the script comes before the keep-gate ruling, and the rest of this package waits for the ruling as planned.
- What it builds. `scripts/release.sh`, which fails closed, in four ways: a dry run, the default, which has `scripts/milestone-build.sh --archive` make the candidate and runs every check on the archive; `--validate`, which adds the export with distribution signing, the checks of what would be uploaded and App Store Connect's own validation; `--upload`, which then uploads the checked `Knot.ipa`, once; and `--rehearsal`, for an agent and the gate, which archives the development flavour signed by nothing and contacts nothing. `scripts/milestone-build.sh` gains `--archive` and `--build-number`. `scripts/lib/bundle.sh` holds what both scripts read of a product.
- Every point of the brief's list for the script is in it: the Xcode from `.xcode-version`, failures through `scripts/lib/fail.sh`, the key as a file path, variable names alone in a dry run, the check for fakes and for debug launch arguments on the archive, a refusal of a candidate without the evidence of every milestone below its level, and the Release configuration.
- The evidence of a milestone is its annotated tag, `m1` to `m7`, at or before the candidate's commit. A tag is the owner's to make, so a level is released only above milestones he has tagged.
- What App Store Connect refuses at an upload, cured here: the App Store icon has no alpha channel, and the three apps declare `ITSAppUsesNonExemptEncryption` false.
- The key is three environment variables, read once and taken out of the environment: the path of the `.p8` file, the key's ID and the issuer's ID. No line the script prints or writes holds them or the team's ID. A validation and an upload refuse every stand-in the self-test uses, and check that the pinned Xcode's `xcodebuild` and `altool` are signed by Apple before either gets the key.
- The upload's outcome, or the sentence that says to check App Store Connect before a retry, reaches the run's log before the terminal. The script never retries an upload.
- What it defends against is an accident: a variable left in a shell, a stale file, a tool that fails, a run cut short. It does not defend against someone who controls the operator's shell or files. App Store Connect's validation is the authority on whether a signature is trusted.
- It changes, by the orchestrator's assignment: `scripts/milestone-build.sh`, `scripts/self-test.sh`, `scripts/lib/bundle.sh`, `scripts/lib/common.sh` and the packaging step of `scripts/verify.sh`, whose two scans now fail on an inspection that failed; the App Store icon's source in `Resources/Brand/`; the three apps' `Info.plist`; and `docs/dev-setup.md`.
- Left for the planned pull request: a level that opens sync, M4 and above, which the script refuses until the tree holds a committed CloudKit schema file; the Mac product, which waits for SP-3; the entitlement audit; the icon sets for every platform; the README, the user guide, the notices, the privacy text and the troubleshooting guide.
- Nothing of it runs for real before the owner's word for one named build: an archive under the milestone's identifiers, distribution signing, the validation and the upload are one sequence, and each upload is his go.

## Failure rules

- Uploading needs Paolo's explicit authorisation and an App Store Connect API key. The key is requested through the secret prompt and never pasted into a thread.
- Each upload needs the owner's word. The API key is handed over for one upload and revoked after it.
- After a failed upload the release script says to check App Store Connect before retrying.
- These also need Paolo's explicit authorisation: moving a tag, distribution signing, notarising, deploying the CloudKit production schema, and every operation on the milestone iCloud container, in either environment.
- The production CloudKit schema cannot drop fields. From the deployment of the production schema on, the CloudKit schema is a committed file, and the gate fails on a change to it that is not additive.
- A release step that was cut short is never resumed. It goes back to the owner (docs/architecture.md §18).
- From the M4 milestone build on, no milestone build is installed or run on the build Mac.
- Milestone builds carry a version above 0.2.0, which is the retired app's. The M7 build is a milestone build.
- The signing team's ID stays out of the repository. `KNOT_LOCAL_CONFIG` names the local file that holds it.
- A package edits only the paths it owns. `Package.swift`, `project.yml`, `AGENTS.md`, `PLAN.md`, `docs/product-spec.md` and `docs/architecture.md` belong to the orchestrator, and a package that needs a change there asks for it in its PR description.
