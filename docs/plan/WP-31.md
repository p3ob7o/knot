## Build

### PR 1

- Controls: Record, New note, and a Search control. The Search control opens the stream with search focused, through WP-19's OpenSearch intent.
- The Record control runs ToggleRecording, which starts a recording when idle and stops the one running, so the control that starts a recording also stops it. The Action Button uses it too.
- The recording Live Activity, with timer and stop. WP-31 owns its views. WP-30 implements `RecordingActivity`, the app-side code of the Live Activity. The Live Activity's attributes type lives in KnotIntents and belongs to WP-19.
- The Live Activity shows whether a recording continues a note or starts a new one, without any text from the note. WP-31 builds that indicator.
- The cues of docs/product-spec.md §4.5 on the iPhone, where the Live Activity carries them. The Live Activity shows saved, then ends. When a recording could not start, it shows the reason. On a locked iPhone it shows the reason and offers to open Knot (docs/product-spec.md §4.4).
- A widget, control or complication may show state without text: a recording with its timer, how many captures are waiting, how many failed.
- The Action Button tip in Settings.
- An iPhone Live Activity may also appear in the Watch Smart Stack and the Mac menu bar. WP-31 checks this, and decides what a tap there does (docs/architecture.md §20).
- The cells of the state matrix in docs/design/brief.md §6 that this package implements are those of the "Outside the app" column marked "Yes", apart from the menu bar, which is WP-33's:
  - Recording, live
  - Recording, before the microphone is live
  - Recording, continues a note or starts a new one
  - Just stopped: saved, with text arriving except on the Watch
  - Short recording discarded
  - Stopped at the limit, by a call, or with the disk full
  - Could not start, with the reason
  - Launchers: idle, recording, waiting, failed. PR 1 holds the controls, and PR 2 the widgets.

## Failure rules

- If a locked start fails, the control opens Knot after Face ID and recording starts at once. SP-1 decides early.
- Extensions never open the database. The widget extension reads recording state from app-group defaults.
- The widget extension links KnotIntents for the types only, and no intent runs there. These rules of docs/architecture.md §14 wait for SP-1 to confirm them: ToggleRecording and StopRecording are compiled into both the app and the widget extension; the Live Activity starts with the recording and lasts as long as it does, or the system stops the recording; if Live Activities are off or the microphone permission is missing, the intent opens the app.
- A stale recording state is judged by a heartbeat, as docs/architecture.md §8 states. Controls show "recording" only while the heartbeat is fresh, and the Live Activity carries a stale date. A press that meets a stale state recovers the orphan and starts a new recording.
- No widget, control or Live Activity shows note text. They show state without text, and the indicator says whether a recording continues a note without any text from the note.
- The cut order. If the build has to shrink, the Home Screen and Lock Screen widgets leave in its second step, and the Sketch control in its first. The Action Button and the controls stay. Scope leaves only on the owner's word, and no agent cuts scope. A part that is cut is not started.
