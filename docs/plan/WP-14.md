## Goal

A raw transcript becomes clean text and a title without changing what was said, or it is left alone.

## Owns

- `Packages/KnotKit/Sources/KnotCleanup/`
- `Packages/KnotKit/Tests/KnotCleanupTests/`
- `knot-eval cleanup`, one of the two commands of the `knot-eval` executable target that WP-01 declares.
- `Fixtures/results/cleanup/`, where it commits the synthetic cleanup results
- `docs/notes/WP-14.md`, the short note of its proof step

The target is `Packages/KnotKit/Sources/knot-eval/`, with its tests in `Packages/KnotKit/Tests/knot-evalTests/`. WP-01 declares both. WP-13 owns `Speech.swift` there and `SpeechCommandTests.swift` among the tests, and WP-14 owns `Cleanup.swift` and `CleanupCommandTests.swift`. Each may add files beside them: every file and every top-level declaration that WP-13 adds starts with `Speech`, and every one that WP-14 adds starts with `Cleanup`, so the two never choose the same name. `main.swift`, `EvalOptions.swift` and `knot-evalTests.swift` are shared files, and a change to any of them goes through the orchestrator. `EvalOptions.swift` reads `--set` and finds the folder for both commands, and holds the exit statuses: 3 for a command that is not built yet, 4 for input that is missing and 5 for a model that is missing. `knot-eval --set synthetic`, with no command named, runs both, speech first, and a command that is not built yet does not fail the other.

## Build

### Proof step

- The fidelity guard first, as a pure function with tests. The short note states its allowed differences as a table: letter case, punctuation, and paragraph and list breaks. That is the table the owner reads at his sitting.
- Run `knot-eval cleanup` on the owner's recordings. It writes ten input and output pairs for the owner to read. If the recordings are not in the folder yet, the note does not wait for them: the thread files it without this run and hands back `needs_owner` for the run, and the orchestrator resumes the thread when the recordings are there.
- File a short note saying whether the draft `Cleaner` port fits the real API's streaming, cancellation and errors. The note is `docs/notes/WP-14.md`, merged by a pull request that holds nothing else.

### PR 1

- The fidelity guard. It compares cleaned and raw text as word sequences. The PR states its allowed differences as a table: letter case, punctuation, and paragraph and list breaks.
- A word may be removed in three cases only: it is in a closed list of fillers; it repeats the word or words that follow it; or it belongs to a short restart whose first word comes again straight after. A negation, a number, a name or a date word is never removed unless the same word survives in the restart.
- Nothing is inserted except punctuation and list markers, and numbers stay as the transcriber wrote them. Any other difference is a changed word, and the guard rejects the result. It also rejects a result that drops more than a set share of the words, and WP-14 sets that share from its evaluation set.
- A mutation suite. For each evaluation transcript it drops a negation, changes a number, swaps a name, reorders two clauses and adds a word, and the guard must reject every one.
- `Cleaner` on Foundation Models: instructions, guided generation of title and body, token budgeting with the model's own counts, chunking on sentence boundaries, and availability (docs/architecture.md §9).
- Cleanup runs with greedy sampling, so the same transcript gives the same result on the same model. Each cleaned segment records the OS build whose model made it, and the cleaner supplies that build with each result.
- A generated title is one line of plain text of at most 60 characters, and it uses only words from the note. That check is one function in KnotCore. KnotCleanup calls it when it proposes a title, and the store calls it when a segment leaves a note. A title that fails the check is dropped.
- The evaluation command is `knot-eval cleanup --set synthetic`. `knot-eval --set synthetic`, with no command named, runs it after the speech evaluation. It runs the 30-transcript set and prints the pass rate. The set includes at least ten meaning-critical cases: negations, amounts, dates, names and spoken self-corrections. The evaluation reports them separately, and it reports with them the cases in which only the punctuation differs.
- `knot-eval cleanup`. It reads the folder of the owner's recordings, which is outside every worktree and named by `KNOT_LOCAL_FIXTURES`, after `knot-eval speech` has written its transcripts there. It writes ten input and output pairs back into that folder for the owner to read, never anywhere else.
- The owner's recordings stay on the build Mac. They are recordings he makes for the build and chooses himself, not notes from his stream.
- `knot-eval` follows docs/architecture.md §18: `--set synthetic` runs on committed fixtures and `--set local` on that folder. Either one exits with a code when its input or its model is missing. It never waits.
- KnotCleanup exposes one live entry point, which returns the unavailable port until WP-14 fills it in. Fill it in, so that the cleaner is wired in without an edit to `Packages/KnotKit/Sources/KnotApp/`.

## Merge criteria

- `scripts/verify.sh --quick` passes.
- The guard tests pass.
- The mutation suite passes: the guard rejects every mutation.
- The PR states the guard's allowed differences as a table.
- The evaluation result is in the PR, with ten examples of input and output for Paolo to read. The examples shown in the PR are synthetic.
- A 10-minute transcript is cleaned in chunks with nothing dropped.
- A result the guard rejects never reaches the store.
- `Cleaner` passes the contract suite of its port on the Mac, in the package tests.
- The merge gate requires the on-device models, and a skipped model test fails it. It checks no accuracy threshold: thresholds belong to this package's PR.
- The synthetic cleanup results are committed with the fixtures. A meaning-critical case that passed and now fails blocks the PR.
- The PR reruns the synthetic evaluation. At the gate the orchestrator runs the local one, as for any PR that touches speech or cleanup, and records the numbers.
- Package tests use Swift Testing and UI tests use XCTest, as docs/architecture.md §17 states.

## Failure rules

- Evidence on quality is thin (docs/architecture.md §20). If the pass rate is poor, Paolo chooses between punctuation-only cleanup and cleanup off by default. A cloud option is a later feature.
- One changed meaning among the meaning-critical cases sends the cleanup default to the owner's decision.
- The guard proves that words are kept. It does not prove that added punctuation keeps the meaning.
- When the model cannot be used on this device, the raw transcript is final. That is a finished state, not an error.
- Cleanup waits when the model is not ready. When the model is only not ready yet, or the system limits requests, the clean job is deferred and runs later. A deferral is never counted.
- A refusal, an empty or malformed result and a guard rejection are treated alike: the raw transcript is the text, and the log records which of them happened.
- No port throws an untyped error. Every failure is a named case of WP-02's error taxonomy, as docs/architecture.md §5 lists them. Among them are cleanup model not ready, cleanup model unavailable, and cleanup declined.
- v1 leaves spoken self-corrections as they were said, and numbers as they were transcribed. Letting cleanup do more is deferred to `TODOS.md`.
- Neither `knot-eval` command prints text from the recordings, and nothing derived from them enters a commit, a PR, a log or a test. The owner's recordings are the one exemption from the synthetic-fixtures rule.
- A PR that changes the cleanup instructions, the guard or the speech settings reruns the cleanup evaluation and `knot-eval`, and states the results before and after.
- The nightly run on `main` reports a model that changed with an update of the operating system.
- Read the SDK before using an OS 26 or OS 27 API. Any such API used is named in the PR with the declaration that was read (docs/architecture.md §21).
