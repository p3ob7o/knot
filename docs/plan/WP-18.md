Everything in WP-18 after its proof step is held until the ruling, which is the keep-gate ruling. When the M2 checklist has passed, the owner uses the M2 milestone build as his only capture tool on the iPhone for seven days. The week ends with the keep-gate sitting, where he rules one of four ways: continue as planned, continue with cuts, revise the spec first, or stop the build. Until that ruling, nothing that the cut order names is built. Seven days pass between the M2 checklist and the start of M5 work. The orchestrator records the ruling in `docs/decisions/keep-gate.md`.

The cut order names the iPad Pencil first: WP-35, the rest of WP-18, the Sketch control and intent, and M5. Scope leaves only on the owner's word, at the keep-gate sitting or at a later milestone sitting. No agent cuts scope. A part that is cut is not started. The orchestrator writes each cut to `TODOS.md` with what would bring it back, and updates the briefs in `docs/plan/` and the checklists in one PR. Ink stays a kind the store knows, so a later version can add it without a migration.

## Build

### Proof step

- Recognise the ink fixtures in the Simulator, and report accuracy and latency.
- Find out whether the `InkRecogniser` contract suite needs the iOS Simulator (docs/architecture.md §5).
- File a short note saying whether the draft `InkRecogniser` port fits the real API's streaming, cancellation and errors. The note is `docs/notes/WP-18.md`, merged by a pull request that holds nothing else.

### PR 1

- The canvas wrapper, with a minimal tool set and a growing canvas, saving at the end of every stroke. Pencil Pro squeeze, barrel roll and hover work as the system tool picker provides them. The canvas is `PKCanvasView` wrapped for SwiftUI.
- A drawing is saved off the main thread, with one save in flight. The target is ink on disk 500 ms after the end of a stroke (docs/product-spec.md §14). It is a target, not a merge criterion: `scripts/verify.sh --perf` measures times at milestones and in WP-42.
- Recognition through `PKStrokeRecognizer`, the read-only renderer, and PNG rendering for export. The recognised text is stored on the segment, so every device can search it without recognising again. KnotInk is on iOS and on macOS, where it is for viewing only (docs/architecture.md §3).
- The Pencil-capability check. It decides whether the canvas is offered: iPad, and iPhone Duo. WP-18 finds the right API for that check on iPhone.
- `DurableFile` in KnotCore is the only code that places a file, and `StoreLocations` the only code that computes a store path. KnotInk uses both and holds no default path, and a file's place on disk comes from its ID.
- KnotInk exposes one live entry point, which returns the unavailable port until WP-18 fills it in. Fill it in, so that WP-18 wires itself in without an edit to `Packages/KnotKit/Sources/KnotApp/`.
- The canvas screens that the iPad and a Pencil-capable iPhone share are not here. They are WP-35's, in `Apps/iOS/Ink/`.

## Failure rules

- Nobody on the project owns an iPhone Duo. That path ships untested on hardware. It sits behind the capability check and is stated as untested.
- If the disk fills while a drawing is being made, the capture stops with the stop cue and says why. What was captured up to then is kept.
- A drawing found at relaunch goes on to recognition, and a recovered capture ends at its last durable write.
- A finished drawing is not reopened in v1. The ink state machine has no transition from ready back to drawing, and writing more starts a new ink segment in the same note. Reopening a finished drawing is deferred to `TODOS.md`.
- Ink opens at M5. In a milestone build made at a lower level, a gate switches it off. WP-01 builds that mechanism, and WP-22 the test that lists the gates for each level.
- No port throws an untyped error. Every failure is a named case of WP-02's error taxonomy, as docs/architecture.md §5 lists them. Among them are recognition failed, and a capture stopped because the disk filled.
- Read the SDK before using an OS 26 or OS 27 API. Any such API used is named in the PR with the declaration that was read (docs/architecture.md §21).
