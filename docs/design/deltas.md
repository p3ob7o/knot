# Design deltas

`docs/architecture.md` §16: the orchestrator lists every difference between the handoff and the built structure here and assigns each one, WP-40's ownership extends to the view models those differences touch, and where the handoff is silent the implementer uses the system default and adds a line here, which the owner clears at M6.

The handoff is in [`handoff/`](handoff/README.md). [`direction.md`](direction.md) gives the order in which the sources rule, and [`handoff-differences.md`](handoff-differences.md) lists where the handoff's two parts differ from each other and from the spec, with what holds for each. The list below was made on 2026-11-26. A reader drew it from the code and the handoff, and a second reader checked it against both.

## 1. Where the handoff differs from what is built

Each difference has the package that owns the files and, where the plan already gives the work to a pull request, that pull request. A difference that names no pull request of the plan is WP-40's, in the sub-package of its platform, and the view models it touches pass to that sub-package with it.

### The theme layer and the tokens

What `Packages/KnotKit/Sources/KnotUI/Theme/` has with no counterpart in `handoff/system/tokens.json`, and the reverse. WP-40's first pull request translates the tokens.

| Role or token | Finding |
|---|---|
| ColorRole.surface | Code role with no token of its own (“.secondary.opacity(0.08)”); nearest tokens fill-tertiary and background-secondary, which tokens.json both name as the notice ground. |
| ColorRole.pending | Code role with no token of its own; the handoff uses label-secondary for pending states. |
| ColorRole.quietMark | Code role with no token of its own; the handoff uses label-secondary for marks. |
| ColorRole.arrived | Code role with no token of its own; tokens.json gives the arrived dot to accent (“the arrived dot”). |
| ColorRole.failed | Counterpart is attention, under another name; value differs (.orange vs #C55300 light / #FF9230 dark). |
