# SP-2 spike: Watch capture and delivery

Throwaway code for spike SP-2 (`docs/plan/SP-2.md`). It lives on the branch `spike/watch-delivery` and never merges. Its short note is `docs/notes/SP-2.md`, and its report will be `docs/spikes/SP-2.md`.

## What it is

A project of its own, generated by XcodeGen from `project.yml`, so it touches nothing of Knot's project:

- **SP2-iOS**, the iPhone app. It receives each file in the delegate call, moves it, checks its SHA-256 against the manifest, acknowledges it with `transferUserInfo`, and records the delivery: its order, the app's state, the process uptime and the background time left. A received recording is transcribed on the phone with `SpeechTranscriber`, inside a background task, and only its word count and timings are kept. When a delivery arrives with the app not in front, the app holds one background task until the system expires it, and records how long that was.
- **SP2-watchOS**, the Watch app. Page one is the record control. Page two runs transfers: 30 generated files of a recording's size, one by one or all queued, and shows the Watch's own timings. Every recording and every generated file stays in the outbox until the phone acknowledges its ID.
- **SP2-WatchWidgets**, the Watch widget extension: the complication (opens `sp2://record`), the Smart Stack widget (a button that runs the foreground intent, with Double Tap), and two controls, one with each intent.
- `Intents/RecordIntents.swift`: two `AudioRecordingIntent`s, one with `supportedModes = .foreground(.immediate)` and one with `.background`, compiled into the Watch app and the extension. Each target's `RecordIntentBridge` logs which process ran the intent.

Identifiers: the development set of `Apps/Config/Identifiers.xcconfig` (`com.p3ob7o.knot.dev`, `.watchkitapp`, `.watchkitapp.widgets`), with the display name "Knot SP-2". No app group, no iCloud container, no entitlements. Another development build with the same bundle ID, such as another spike's, is replaced when this one is installed.

Each app writes an event log, `Library/Application Support/SP2/events.jsonl` in its container: IDs, names, numbers and error codes, never text of a recording.

The recorder refuses to start in the Simulator, whose microphone is the Mac's.

## Build for the simulators

```
export KNOT_AGENT=1
Spikes/SP-2/build.sh sim      # builds, boots this worktree's iPhone and Watch, installs both
Spikes/SP-2/build.sh check    # also compiles for devices, unsigned
Spikes/SP-2/sim-test.sh watch run -sp2-count 5 -sp2-mode sequential
```

`sim-test.sh` launches one app with a test and prints what both event logs gained. The tests are listed in `Watch/Sources/LaunchTests.swift`. In the Simulator, files and user info from the Watch never reach the phone app; see `docs/notes/SP-2.md`.

## Build for the devices

1. `KNOT_LOCAL_CONFIG` names the local configuration that sets `KNOT_SIGNING = team` and `DEVELOPMENT_TEAM`. The script gives it to the build alone, as `-xcconfig`, and links nothing into the worktree.
2. Xcode is signed in to the team's account. The build passes `-allowProvisioningUpdates -allowProvisioningDeviceRegistration`, so the first one registers the development app IDs and any connected device that the account lacks. A Watch is registered only by a build whose destination is the Watch itself: build the `SP2-watchOS` scheme once with `-destination id=<Watch UDID>` and those two flags, then run the script. Developer Mode is on on both devices, and the Watch is paired with the iPhone.
3. Find the iPhone's and the Watch's identifiers with `xcrun devicectl list devices`. Then, with the pinned XcodeGen first on `PATH`:

```
KNOT_LOCAL_CONFIG=<file> SP2_PHONE=<iPhone identifier> SP2_WATCH=<Watch identifier> Spikes/SP-2/build.sh device
```

The script builds, checks that the app is signed with a team, and installs the iPhone app and then the Watch app embedded in it.

Then follow `sitting.md`.
